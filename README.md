# Расписание (офлайн + Google Таблица)

Простое веб-приложение для общего расписания: записи по датам и времени, с типами/цветами (клиент, мероприятие, задача), работают на телефоне и компьютере. Записи сохраняются локально в браузере и, при настройке, синхронизируются с Google Таблицей через Google Apps Script.

## Что умеет

- **Формат расписания**: даты сгруппированы, внутри — время и информация (`15.11 11:00 — ...`).
- **Любая информация**: не только клиент, но и мероприятие/задача.
- **Цвета/типы**: клиент, мероприятие, задача — разным цветом; цвет можно выбрать вручную.
- **Офлайн**: интерфейс и данные работают без интернета (Service Worker + localStorage).
- **Отложенная синхронизация**: если интернет пропал во время записи, запись сохраняется локально и попадает в очередь; при следующем подключении отправляется в общий лист.
- **Общий лист**: Google Таблица как общее хранилище для нескольких сотрудников.

## Быстрый запуск локально

Нужен любой статический HTTP-сервер (Service Worker не работает через `file://`).

```powershell
# Вариант 1: Python
python -m http.server 8080

# Вариант 2: Node.js (если установлен)
npx serve .
```

Откройте `http://localhost:8080`.

## Настройка Google Таблицы (общий лист)

1. **Создайте Google Таблицу**. Можно назвать лист `Schedule` (или поменять `SHEET_NAME` в `apps-script/Code.gs`).
2. Откройте **Расширения → Apps Script**.
3. Вставьте содержимое файла [`apps-script/Code.gs`](apps-script/Code.gs).
4. Нажмите **Deploy / Развернуть → New deployment / Новое развёртывание**.
5. Тип: **Web app / Веб-приложение**.
6. Параметры:
   - **Execute as / Запускать от имени**: *Me / Я*.
   - **Who has access / У кого есть доступ**: для команды обычно *Anyone / Все* или *Anyone with the link*. Выбирайте согласно вашей политике доступа.
7. Разверните и скопируйте **Web app URL** (`https://script.google.com/macros/s/.../exec`).
8. В приложении откройте **Настройки** и вставьте URL.
9. Укажите имя устройства/сотрудника (опционально, сохраняется в записи).

После этого записи будут отправляться в таблицу и подтягиваться из неё.

## Как работает офлайн и синхронизация

- Каждая запись сохраняется в `localStorage` сразу.
- Изменения попадают в локальную очередь (`outbox`).
- Когда есть интернет и настроен Apps Script URL, приложение отправляет очередь и затем подтягивает данные из таблицы.
- При конфликте используется стратегия **last-write-wins** по полю `updatedAt` (у кого изменение новее, то и остаётся), кроме случая локальной незавершённой отправки: локальное изменение остаётся в очереди и будет отправлено.
- Удаление — мягкое (`deleted=true`) для корректной синхронизации.

## Важные ограничения

- **Это не полноценная система авторизации**. Режим "общая ссылка/Apps Script" удобен, но URL фактически является ключом доступа. Не публикуйте его публично.
- **Google Apps Script** имеет квоты и задержки; для небольшого расписания обычно достаточно.
- **localStorage** привязан к браузеру/устройству. До синхронизации данные есть только на устройстве, где созданы.
- Для строгой многопользовательской безопасности и разграничения прав лучше перейти на backend с аутентификацией (Google OAuth/Firebase/Supabase/свой сервер).

## Формат данных в таблице

| Колонка | Описание |
|---|---|
| `id` | Уникальный ID записи |
| `date` | Дата `YYYY-MM-DD` |
| `time` | Время `HH:MM` |
| `info` | Текст записи |
| `type` | `client` / `event` / `task` |
| `color` | HEX-цвет |
| `updatedAt` | ISO-время последнего изменения |
| `deleted` | `true/false` |
| `sourceDevice` | Имя устройства/сотрудника |

## Проверка

1. Откройте приложение, добавьте запись.
2. В DevTools выключите сеть/включите Offline — запись должна остаться и отображаться.
3. Добавьте ещё запись офлайн — она получит статус "Ждёт отправки".
4. Включите сеть — нажмите "Синхронизировать" или дождитесь авто-синхронизации.
5. Проверьте строку в Google Таблице.
